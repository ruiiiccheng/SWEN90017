# Sprint 0 Plan — Discovery and Executable Baseline

## Sprint duration

To be agreed. This plan is suitable for a short discovery sprint aligned with the next client review.

## Sprint goal

Create a shared, evidence-based product baseline and a reproducible technical starting point so Sprint 1 can deliver a coherent vertical slice without hidden architecture or scope assumptions.

## Candidate Sprint 0 backlog

| Item | Outcome | Primary owner |
|---|---|---|
| DISC-01 CRM benchmark | Individual product reviews and consolidated feature matrix | Split across team |
| DISC-02 starter-code audit | Running baseline and working/partial/missing map | Technical pair |
| DISC-03 MVP/context decision | Product-owner-approved scope and demo scenario | Product Owner + whole team |
| DISC-04 data dictionary | Core fields, relationships, statuses and open rules | Analyst pair + client review |
| DEL-01 Git/project memory | Branch/PR rules, templates, decision log and member memory | Scrum Master / repo steward |
| DEL-02 environment/CI | Documented startup, migrations and initial CI checks | DevOps pair |
| DEL-03 synthetic data | Safe seed dataset plan or implementation | Developer |
| DEL-04 architecture spike | ADR-0001 with selected option | Technical team |
| Backlog refinement | Ordered MVP stories with team estimates | Whole team + Product Owner |
| Scrum setup | Cadence, roles, ceremonies and review schedule | Whole team |

## Exit criteria

- Every team member can access the repository.
- At least two team members can run the inherited or chosen baseline from a clean checkout.
- The feature/gap matrix and data dictionary are in the repository.
- The Product Owner has confirmed the target context, MVP boundary and first AI use case or has explicitly scheduled the decision.
- ADR-0001 records the architecture decision or a constrained interim decision.
- Sprint 1 stories meet the Definition of Ready and have team-owned estimates.
- Known risks, assumptions and unresolved client questions are current.

## Review demonstration

1. Show the running baseline.
2. Show the system capability/gap map.
3. Walk through the approved core entity model and first end-to-end scenario, supported by early low-fi wireframes.
4. Present the architecture decision and trade-offs.
5. Confirm Sprint 1 goal and selected backlog with the Product Owner.
