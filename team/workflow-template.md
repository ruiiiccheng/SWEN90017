# Personal Workflow — <Name>

## Before starting a story

1. Read the story, source trace and acceptance criteria.
2. Confirm dependencies and current architecture decisions.
3. Create/link the GitHub issue and branch.
4. Write a small implementation/test plan in the issue or PR.

## During implementation

1. Keep changes scoped to the story.
2. Add tests with the behaviour.
3. Update migrations/data fixtures when required.
4. Record new assumptions as questions or decisions, not hidden code behaviour.
5. Review AI-generated code and prompts; do not merge unexplained output.

## Before requesting review

1. Run formatting, tests and migrations locally.
2. Demonstrate each acceptance criterion.
3. Update documentation and source trace.
4. Complete the PR checklist and identify remaining risks.
