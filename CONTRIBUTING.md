# Contributing

1. Select a Ready story or approved bug and link a GitHub issue.
2. Create a scoped branch using the working-agreement naming convention.
3. Implement behaviour and tests together.
4. Keep database migrations small, ordered and reviewable.
5. Open a pull request using the template; show evidence for every acceptance criterion.
6. Obtain review from at least one teammate and resolve comments.
7. Merge only when CI passes and documentation/decision records are current.

Do not commit secrets, real client data, generated build artefacts or Salesforce-branded/copied interface assets.
